# 使用自己的服务部署

本指南描述独立Linux服务器环境，不提供维护者的域名、机器、数据库或凭据。Mac只运行前端、Python和测试，不启动基础服务容器。

## 基础服务与配置

安装Docker Compose、Node.js 22及构建所需工具，克隆公开快照。进入backend，复制`.env.example`为`.app.env`，权限设为600。配置独立强密码、随机CURSOR_SECRET、SMTP及验证码秘密；需要AI功能时另填模型、向量和转写配置。

正式环境设置：`APP_ENV=production`、`COOKIE_SECURE=true`、`APP_URL=https://你的域名`、`ALLOWED_ORIGINS=["https://你的域名"]`。`TRUSTED_PROXIES`只填实际Nginx到API的代理地址，不使用通配符。设置`AI_AGENT_IMAGE=ai-agent-api`、`AI_AGENT_RELEASE=local`。开发或测试与真实用户数据分开配置，不共用数据库和Redis命名空间。

在自己的Linux服务器backend目录执行：

```bash
docker compose --env-file .app.env up -d --wait db redis rabbitmq
docker build -t ai-agent-api:local .
docker compose --env-file .app.env -f compose.yaml -f infra/deploy/app.compose.yaml --profile app run --rm --no-deps api alembic upgrade head
docker compose --env-file .app.env -f compose.yaml -f infra/deploy/app.compose.yaml --profile app up -d --no-deps --no-build api worker summary-worker
```

已有数据升级前先备份并核对迁移，禁止把测试库清理或downgrade命令用于业务库。Redis配置为noeviction；额度、会话和租约不可用时需排查服务，不应通过清空共享Redis恢复。RabbitMQ、Redis及数据库仅绑定回环。

## Web入口

在frontend执行 `npm ci && npm run build`。将dist发布到自己的静态站点。`backend/infra/deploy/nginx.conf`是示例，需替换`app.example.com`、证书及静态目录，核验配置后启用。API转发到回环18000，清除外部伪造的转发地址头。TLS证书申请、续期和备份由部署者配置。

验证回环 `http://127.0.0.1:18000/ready` 返回status/database均ok；公网首页、JS、CSS和对话路由正常，未登录`/api/auth/me`返回401。检查celery与assistant-summary队列各有消费者。自定义ASSISTANT_SUMMARY_QUEUE时同步应用和摘要Worker命令，不能只启动一个回答Worker。

升级时从同一版本构建镜像，先验证配置、迁移、健康及队列再切换，保留旧镜像和静态目录。若回滚到没有后台摘要任务的旧版本，先停止新增摘要Worker再恢复旧配置。本文不是对任何云主机执行过的发布记录。
