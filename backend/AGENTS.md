# 后端开发规则

同时遵守仓库根目录的 `AGENTS.md`。

## 目录与职责

- `src/backend/app.py` 保持应用组装、中间件和异常处理入口，启动路径保持 `backend.app:app`。
- `src/backend/api/routes/` 放 HTTP 路由，`api/schemas.py` 放请求响应契约；契约变复杂时按功能拆分，不继续堆积在单个文件。
- `src/backend/core/` 放配置、会话和安全依赖；`src/backend/db/` 放数据库连接、会话和模型，二者不得反向依赖 API 路由。
- 路由负责协议处理与调用，复杂或被复用的业务逻辑按功能提取独立模块；不把业务逻辑塞进通用 `core/`，不预建 Repository 或服务框架。
- `migrations/` 放 Alembic 迁移，`tests/` 放测试，`infra/` 放基础设施工具，`openspec/` 放后端 SDD。不得在包根目录平铺新增业务模块。

## 实现与检查

- 使用 uv 管理依赖并同步 `uv.lock`，沿用 FastAPI、Pydantic 和同步 SQLAlchemy；不无依据地改造为另一套框架或异步架构。
- 配置通过现有 Settings 和环境变量读取，禁止硬编码凭据；移动配置模块时核对 `.env` 的解析路径。
- 所有输入在服务端校验，资源归属从已验证会话确定，每次资源访问均执行权限与归属检查，不信任客户端传入的用户身份。
- 保持统一错误响应，不向客户端泄露内部异常或秘密；日志不得记录密码及会话令牌。
- 业务操作显式管理提交与回滚，拆分不能破坏事务边界、并发约束或幂等性。表结构变化必须通过经审阅的 Alembic 迁移，不在应用启动时自动建表，不修改已应用的历史迁移。
- 使用 Ruff 格式化。在 `backend/` 执行 `uv run ruff format --check src tests migrations infra` 和相关 pytest 测试；数据库或 Redis 变化需在专用云端测试环境验证。
- LangGraph、Celery 等能力仅在对应需求落地时接入；已安装依赖不代表业务能力已实现。

## Python 文件行数限制

- 本目录及其子目录中的每个 `.py` 文件不得超过 **300 行**；`migrations/versions/` 下的数据库迁移文件豁免。
- 以项目 Ruff 格式化后的实际文件行数为准，包含空行和注释；禁止通过压缩代码或删除必要注释规避限制。
- 开发过程中，新增或修改的 Python 文件一旦超过 300 行，必须在继续扩展功能前完成拆分；交付前再次确认不超过限制。
- 修改已有超限文件时，应一并将其拆分至符合限制。
- 按路由、业务逻辑、数据模型、请求响应契约及基础设施等实际职责拆分，保持现有接口、事务边界、鉴权和错误处理行为不变，避免为凑行数引入无意义的模块或抽象。
- 拆分后运行 Ruff 格式检查和相关测试；涉及数据库、会话或外部服务时，执行相应的集成验证。
