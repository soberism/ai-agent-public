# 前端开发规则

同时遵守仓库根目录的 `AGENTS.md`。

## 目录与依赖方向

- `src/main.tsx` 保持启动入口；`src/app/` 管理路由、应用级 Provider 和登录守卫，不堆放业务页面。
- `src/features/<功能>/` 放对应页面、业务组件、Hooks、类型和校验规则。业务专属代码留在所属功能内。
- `src/shared/` 仅放与具体业务无关的组件、HTTP 客户端和工具，不得反向依赖 `features/` 或 `app/`。
- `src/styles/` 维护公共样式，沿用项目设计规范；`tests/` 放测试，`openspec/` 放前端 SDD。
- 新文件按职责放入现有目录，不在 `src/` 根目录平铺业务文件；复杂功能按需继续拆分，不为未来需求预建目录。

## 实现与检查

- 沿用 React、TypeScript、React Router 和现有请求客户端；不为单个功能引入重复的路由、请求或状态管理方案。
- UI 采用渐进式沉淀：修改页面前先复用已有设计变量、公共样式和共享组件；同一种视觉或交互模式在两个及以上位置重复时，再提取为共享组件，避免一次性重构和重复实现。
- 同类控件的尺寸、圆角、颜色、间距、状态和交互保持一致；公共视觉值优先使用 `src/styles/` 中已有变量，不在业务组件中另起一套风格。
- 新增共享组件前确认现有 `src/shared/` 没有同等能力；共享组件只承载稳定、跨业务的行为，业务差异继续留在 `src/features/`。
- 用户文案使用中文，优先适配手机 H5；保留语义化标签、表单标签、键盘操作和焦点管理。
- 请求、响应及状态应有明确类型，不用 `any` 或无依据的类型断言绕过检查。加载、空数据、失败和会话失效分别处理，不把请求失败显示为操作成功。
- 沿用同源 `/api` 和服务端 Cookie 会话，不自行改为浏览器存储令牌；涉及账号切换、迟到响应和写请求重试时，保持现有隔离与幂等约束。
- 使用 Prettier 格式化、ESLint 检查 TypeScript 和 React Hooks；不得为消除告警随意关闭规则或删除必要依赖项。
- 在 `frontend/` 执行 `npm run format:check`、`npm run lint` 和 `npx tsc -b`；涉及交互时运行相关浏览器测试，涉及构建配置时运行 `npm run build`。

## 统一视觉约束

- Toast 统一复用全局 `.toast`：浅紫底深紫文字、淡紫边线和轻阴影、错误为浅红底红字、顶部居中、内容自适应宽度、约 3 秒自动消失；不得在模块中另定义 Toast 配色或定位。Toast 应渲染到不受 transform 影响的根层。
- 按钮沿用公共语义色：主操作和确认操作为深色白字，轻操作为紫色，危险操作为红色；禁用态复用公共规则，纯图标按钮禁用时保持透明背景。
- 页面左上角返回控件只显示 `<` 形左箭头，不展示“返回”等文字；保留 `aria-label="返回"` 和至少 44px 点击区域。
- 返回控件统一复用 `BackButton`，有应用内历史时返回上一页；直接打开无应用内历史时使用对应模块默认入口，不固定跳转替代历史返回。

## TSX 行数规则

- 本目录及其子目录中的每个 `.tsx` 文件不得超过 **200 行**。
- 以项目 Prettier 格式化后的实际文件行数为准，包含空行和注释；禁止通过压缩代码或删除必要注释规避限制。
- 开发过程中，新增或修改的 TSX 文件一旦超过 200 行，必须在继续扩展功能前完成拆分；交付前再次确认不超过限制。
- 修改已有超限文件时，应一并将其拆分至符合限制。
- 按职责拆分页面、组件、Hooks、类型与工具函数，保持现有行为、接口和样式不变，避免为凑行数进行无意义拆分。
- 拆分后运行相关 ESLint、类型检查及必要的回归验证。
